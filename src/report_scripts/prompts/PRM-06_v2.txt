Составь PersonalOverlay для заданной роли пользователя.
event_core — предыдущий неподтверждённый разбор; каждую его мысль сверь с ledger.
why_you объясняет связь конкретного известного признака компании и события.
Каждый why_you ссылается хотя бы на один COMPANY_FEATURE, а также на событие
или расчёт. Известный отраслевой prior не выдавай за факт о договорах компании.
impact_chain содержит factor, effect, text, source_ids и уникальный id.
factor используй только из effect_signs, effect копируй строго из effect_signs.
Укажи механизм: событие → канал → известный признак → условное последствие.
В source_ids включи effect_source_ids[factor] и доказательства связи с компанией.
При two_branches изложи оба условных исхода и задай вопрос, который их различит.
Не утверждай определённый риск или выгоду там, где знак неизвестен.
Минимум два фактора объясни, если два доказанных канала есть на входе;
если есть только один, используй один и честно укажи ограничения.
Не выводи экспорт/импорт из одного флага ВЭД или страны. Не угадывай сумму долга.
risks и opportunities должны быть согласованы с рассчитанными знаками.
actions_or_questions: не более четырёх конкретных вопросов для проверки или обсуждения.
В unknowns перечисли ограничения. Не включай персональные данные физических лиц.
У source_ids есть только ID из ledger.entries. ID всех утверждений начинай с personal_.

Ограничение объёма: до двух why_you, до трёх impact_chain, по одному risks и opportunities, до двух actions_or_questions. Одно короткое предложение на запись. При неизвестном признаке допустима явная констатация отсутствия данных со ссылкой на этот признак.
