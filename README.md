# NAFA — часть Prompt Engineer

Этот пакет превращает новости, аналитику банка и готовые расчёты DA в объяснение для руководителя компании: что произошло, почему это касается его бизнеса, какие последствия возможны и что стоит проверить.

Карточка разделяет **факт**, **позицию Альфа-Банка** и **вывод AI**. Утверждения ссылаются на доказательства. Числа и знак эффекта передаются из кода; ответ проверяет модель другого семейства. При ошибке есть один цикл исправления, затем карточка блокируется.

## Быстро посмотреть результат

Нужны Python 3.11+ и `uv`. Из корня репозитория:

```bash
uv sync --dev
uv run python -m pe.run replay examples/demo/case.json --responses examples/demo/responses --out out/demo
```

Откройте `out/demo/preview.md`. Это синтетический пример с заранее записанными ответами: ключ и платные вызовы не нужны. В `card.json` лежит карточка, в `result.json` — проверки и история шагов.

Проверить код:

```bash
uv run pytest -q
```

## Что входит в пакет

- Все 17 промптов из ТЗ: извлечение, вектор влияния, PDF, позиция банка, общий и персональный разбор, критик, диалог, объяснения расчётов и графиков, предложения банка и независимая оценка.
- Входные и выходные JSON-схемы, реестр доказательств и проверка ссылок, знаков чисел, единиц и дат.
- Ограниченные повторы: исправление JSON и один общий цикл исправления карточки; общий лимит вызовов.
- Адаптеры карточки к формату backend и выгрузка трасс для оценки DA.
- Тесты на 1000 синтетических примерах, исполняемые seed-сценарии команды, 20 разных атак и карточки с внесёнными ошибками.
- Скрипты сравнения разрешённых моделей и таблица токенов по операциям.

Фактические результаты и оставшиеся внешние условия приёмки: [отчёт](docs/pe/evaluation/acceptance_summary.md). Результат 999/1000 в тесте структурированного аудита относится к этой узкой задаче; качество полной карточки оценивается отдельно. Дообучение модели не выполнялось.

## Подключить API организаторов

Локальные веса моделей скачивать не нужно. В корневом `.env` задайте:

```env
LLM_BASE_URL=https://changellenge.up.railway.app/v1
LLM_API_KEY=ключ_команды
```

`.env` исключён из Git. Адрес и точные имена моделей закреплены в `config/organiser_models.json`; [инструкция организаторов](https://docs.google.com/document/d/1ly8GsI_-oPnCQWvtZ4nGevnnDP2MGYIfpn2zOUFxZ_4/mobilebasic).

Установите зависимости API и один раз подготовьте локальную копию шлюза из ветки backend:

```bash
uv sync --dev --extra backend
uv run python scripts/prepare_backend.py
```

Если `.local/backend` уже существует, повторная подготовка остановится, сохранив настройки. Скрипт использует закреплённую ревизию из Git и не сливает ветки. Полный backend и сбор данных здесь не запускаются.

Проверить все промпты и сравнить генераторы:

```bash
uv run --env-file .env --extra backend python -m pe.acceptance matrix --out out/acceptance
uv run --env-file .env --extra backend python -m pe.acceptance cards --out out/acceptance
```

Платные CLI-прогоны используют POSIX-таймер и запускаются на macOS/Linux в основном потоке. Общий предел одного обращения к шлюзу — 300 секунд, включая его сетевые повторы; затем прогон сохраняет ошибку и останавливается. Этот предел относится к CLI оценки; рабочий backend задаёт свой общий тайм-аут запроса.

Это реальные вызовы. Бюджет **500 ₽/день общий для всей команды**. Результаты сохраняются после каждого случая; повторный запуск с теми же промптами и кодом продолжает сохранённый прогон. При смене версии используйте новый каталог. Тарифы в рублях пока не подтверждены: неизвестная цена обозначается `null`, а не нулём. Для VLM-проверок нужен `pdftoppm` из Poppler. Сырые страницы VLM требуют сверки и блокируются на входе извлечения позиции банка до неё; [найденные ошибки](docs/pe/evaluation/vlm_review.md).

Дополнительные проверки:

```bash
uv run --env-file .env --extra backend python -m pe.acceptance critics --out out/acceptance
uv run --env-file .env --extra backend python -m pe.acceptance critic-controls --out out/acceptance
uv run --env-file .env --extra backend python -m pe.acceptance attacks --out out/acceptance
uv run --env-file .env --extra backend python -m pe.acceptance judge --out out/acceptance
uv run python scripts/report_acceptance.py --run out/acceptance
```

Локальный ограничитель эксперимента по умолчанию равен 2 млн токенов за день. Для явно заданного другого запаса есть `scripts/resume_acceptance.py <phase> --out out/acceptance --token-limit 3000000`; общая база, кэш и серверный лимит 500 ₽ сохраняются. Это не подтверждает рублёвую стоимость.

Сохранённые успешные ответы можно повторно проверить после изменения локальных проверок через `scripts/revalidate_matrix.py --source out/old --out out/new`. Скрипт проверяет совпадение промпта и схемы, повторяет проверки источников и чисел, сохраняет исходную телеметрию и отмечает повторное использование. Это не новые вызовы моделей.

После подтверждения тарифов заполните копию `config/pricing.example.json` и выполните `uv run python scripts/calculate_budget.py --prices .local/prices.json`. Калькулятор использует измеренные токены и план вызовов `config/card_budget_plan.json`; без тарифов стоимость и ёмкость остаются `null`. Оценка по средним токенам требует отдельного запаса на исправления и сбор источников.

## Как подключить к backend

`CaseInput` в `pe/pipeline.py` принимает извлечённое событие, псевдоним клиента, роль, реестр источников и ссылки на **готовые** значения DA: релевантность FM-06, уверенность FM-20 и знаки эффекта. Файлы физических лиц в запрос модели не передаются.

`run_case(case, gateway)` выполняет генерацию и проверки. Хост передаёт адаптер существующего `LLMGateway`; `pe/run.py` содержит готовый адаптер. Для ограничения глубины рассуждений шлюз должен поддерживать `request_options`; совместимое расширение локальной копии находится в `pe/gateway_patch.py`.

Готовый [патч шлюза](patches/backend_gateway.patch) добавляет эти параметры в ключ кэша и корректно учитывает пустой ответ API. Его можно отдельно применить в ветке backend; подготовка `.local/backend` уже включает это расширение.

После успешной проверки:

- `pe.integration.backend_payload(card, case)` — карточка для API и интерфейса;
- `pe.integration.quality_trace(card, ledger)` — утверждения и основания для контура оценки DA;
- `pe.integration.load_da_features(...)` — чтение разрешённых агрегатов из выгрузок DA;
- `pe.tasks.run_task("PRM-08", payload, gateway)` — диалог с проверкой атомарных утверждений независимым критиком.

Хост проверяет `result.publishable` до показа и передаёт в API/интерфейс также `result.partial`, `result.unknowns` и сведения об удалённых утверждениях из `result.discarded_claims`. Эти поля относятся к результату проверки и не выводятся из одного объекта карточки.

`publishable=true` возможен только в реальном режиме после успешных проверок. Режимы `replay` и `evaluation` не разрешают публикацию синтетического результата.

## Кандидат на улучшение качества

Структурированные причинные связи, проверяемые условия изменения вывода и полезные вопросы реализованы отдельными версиями PRM-06 v5/v6. Базовая v4 остаётся рабочей. [Протокол и команды честного A/B](docs/pe/07_improvement_protocol.md) описывают отдельные наборы, замороженную рубрику, бюджет и блокировку закрытого теста.

Реальные CSV участников скачаны и обработаны закреплённым DA. [Данные, исправление CLIENT и честные результаты A/B](docs/pe/08_real_participant_data.md): целевой балл 4.5 пока не подтверждён, рабочая версия сохранена.
