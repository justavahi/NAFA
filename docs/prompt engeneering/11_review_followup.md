## Описание роли

`pe.context.role_card()` читает все шесть ролей из `reference/persona_weights.csv`:
название, задачу, темы, горизонт и веса факторов. В трассу попадает SHA256
справочника. Неизвестная роль отклоняется. Роль не становится основанием для
утверждений о продуктах, договорах или полномочиях клиента.

Отдельные профили в `prompts/profiles/`:

| Профиль | Генератор | Контекст |
| --- | --- | --- |
| baseline_v1.json | плоский v4 | прежний код роли |
| context_control_v1.json | плоский v7 | прежний код роли, без карточки и отбора |
| role_context_v1.json | плоский v7 | карточка роли |
| fragment_focus_v1.json | плоский v7 | выбранные атомарные NEWS_FACT |
| role_focus_v1.json | плоский v7 | оба изменения |

v7 расширяет v4 инструкциями о контексте, без InterpretationPlan. Поэтому сравнение
с baseline оценивает весь пакет инструкций и контекста. Чтобы изолировать влияние
одного поля роли подготовлен `context_control_v1.json` с тем же v7 и `role_card=null`.
Структурные проверки на трёх ролях подтверждают передачу контекста, но не доказывают,
что ответы модели стали различаться полезным образом.

## Фрагменты и проверка связи

`fragment_news(document)` выделяет предложения/строки, сохраняет точные Unicode
смещения и текст. ID зависит от документа, всего текста и границ. Десятичные
числа и распространённые сокращения сохраняются. Это синтаксическое разбиение:
сложные сокращения, таблицы и межфразовая атрибуция требуют просмотра человеком.

`attach_news_fragments(ledger)` добавляет ссылки в копию реестра. Исходные цитаты,
документы и зависимости расчётов DA сохраняются: разбиение текста не пересчитывает
экономический смысл формул. Факторы, тип содержимого и достаточность контекста
автоматически не подтверждаются.

Для focus-профиля хост явно передаёт непустой `selected_news_ids`. Принимаются
только NEWS_FACT с точными атомарными границами. PRM-05 получает выбранные NEWS
и все BANK_VIEW. Полные документы остаются для проверки атрибуции и конфликтов.
Это ограничение допустимых ссылок, а не удаление остального текста из контекста.

Проверка перед критиком требует, чтобы каждый показанный факт ссылался только
на выбранные фрагменты, а каждый такой фрагмент напрямую цитировался в `why_you`
или `impact_chain`. Широкая зависимость расчёта от всего абзаца не засчитывается.
При нарушении запускается штатное исправление, затем карточка удерживается,
если ошибка осталась. Факт не удаляется молча ради прохождения проверки.

Совпадение ID доказывает связность ссылок, а не причинную или фактическую
корректность. Семантический критик сохранён для всех слоёв, включая факт/прогноз,
позицию банка, даты, единицы и условия. Автоматический `retry_search` для focus
отклоняется: новый источник требует новой проверенной подборки.

Пример подключения к существующему шлюзу:

```python
import json
from pathlib import Path
from pe.context import attach_news_fragments
from pe.pipeline import CaseInput, run_case

payload = case.model_dump(mode="json")
payload["ledger"] = attach_news_fragments(case.ledger).model_dump(mode="json")
atomic_case = CaseInput.model_validate(payload)
manifest = json.loads(Path("prompts/profiles/role_focus_v1.json").read_text())
# reviewed_ids выбирает человек/хост после проверки содержания и контекста.
result = run_case(atomic_case, gateway, manifest=manifest,
                  selected_news_ids=reviewed_ids)
```

## Материалы для проверки и следующий эксперимент

`scripts/prepare_context_review.py --out <новая-папка>` создаёт карточки ролей
и пустую CSV-разметку DOC-07, страница 1. Подготовленный комплект находится
в `evaluation/context_review_v1/`. Поля факторов, типа (событие/прогноз/фон),
атрибуции и достаточности контекста оставлены пустыми. Проверенных человеком
меток сейчас 0; независимая истинность текста корпуса не установлена.
В тексте есть внутренняя неоднозначность: «снизился с 6,0% до 6,1%». Нужна
сверка с PDF; исправлять направление по догадке или считать строку эталоном нельзя.

Перед API-сравнением: проверить фрагменты и PDF, заморозить новый протокол,
взять одинаковые события/клиентов для всех вариантов. Контроль роли проводить
на PER-01/PER-03/PER-04; сравнивать обоснованные решения, вопросы и ошибки,
а не только оценку судьи. Нужны новые события с разными каналами и независимые
слепые оценки людей. Старый закрытый test остаётся закрытым.

Новые API-вызовы в этой итерации не выполнялись; метрики старых запусков не
являются результатом новых кандидатов. Лимиты старых исследований не сброшены.
Не реализованы автоматический классификатор фрагментов, экспертные экономические
правила, калибровка судьи и оптимизация семантического критика. Дообучения не было.

Две оговорки к внешнему разбору: один доступный канал ограничивает проверку плана,
но не предопределяет ничью. Сумма медиан задержек этапов не равна медиане задержки
всей карточки; долю reasoning-токенов без отдельной телеметрии утверждать нельзя.
