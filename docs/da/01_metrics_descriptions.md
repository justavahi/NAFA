## 2. Итоги профилирования (WP-D1)

Проверки по разделу 3.1 ТЗ. Профилирование выполняется автоматически (`analytics/profiling.py`), полный отчёт: `out/profiling/report.md` (артефакт прогона).

| Блок | Что проверено | Результат и действие |
|---|---|---|
| Размер и ключи | Строки, уникальность `SYNTHETIC_U` | 11 дублей ID → дедупликация `keep=first` перед расчётами (первая строка канонична) |
| Масштаб | Доля выручки ≥ 15 млрд | 0,1% — против ожидания для «крупного бизнеса»; единицы `REVENUE_COMPANY` не подтверждены → OQ-02 |
| Пропуски | Доля NULL по полям | Продуктовые флаги у `PROSPECT` пустые — трактуем как «неизвестно», не как «нет продукта» (правило ТЗ) → OQ-03 |
| Словари | ECO_MARK_LABEL, OKFS_NAME, ORG_TYPE, градации | Словари извлечены в `out/dictionaries/report.md`; для стадий определён `growth_flag` (Рост/Запуск → 1) |
| Продукты | 7 флагов + FACTORING | Значения 0/1; NULL у потенциальных клиентов; FACTORING_MARK восстанавливается в `F08_FACTORING` |
| ФНС и СПАРК | Согласованность градаций численности | Доля конфликтов и тепловая карта — CH-03; конфликт идёт в `F13_noise_flags` |
| ВЭД | FTS_FLAG, FTS_COUNTRY_NAME | Собран словарь страна → валюта (`out/dictionaries/report.md`), риск-тиры стран для E-12 → OQ-04 |
| NEGATIVEMARK | Распределение, связь с полями | Семантика расходится с описанием кейса → OQ-05 |
| Группы | GROUP_ID: размеры, отраслевая однородность | Учтено в F-11 и GR-01; аномальная компонента 750 → OQ-06 |
| Графы | Компоненты GR-01, рёбра и покрытие GR-02 | 18 037 компонент / макс 750; 1,38 млн рёбер; покрытие SP 70,4% — глубина FM-22 k=2 подтверждена |
| География | Пустые CITY/REGION, согласованность с RC_NAME | `F07_home_region/city` + регионы связанных физлиц; энтропия F-07 |
| Платежи | Идентификаторы вне клиентской базы, нули, самоплатежи | Часть контрагентов не найдена среди клиентов (30% рёбер) — учитывается как «внешние», вклад через prior отрасли клиента; самоплатежи исключены |
| Покрытие SP | Распределение клиентов по профилям | Полная таблица — в Приложении A; непокрытых ОКВЭД нет (WP-D2: 100% кодов отнесены) |
| Выбросы | Экстремумы выручки и платежей | Winsorization только для графиков (CH-01), расчёты — на исходных значениях |

## 3. Расхождения с кейсом — вопросы организаторам/BA (OQ)

| ID | Вопрос | Кому | Влияние на расчёты |
|---|---|---|---|
| OQ-01 | 11 дублей `SYNTHETIC_U` (например `U_428697`) — ошибка выгрузки или разные записи? | Организаторы | Сейчас: `keep=first`. Если записи различаются — пересобрать |
| OQ-02 | Единицы `REVENUE_COMPANY`: если тыс. руб., крупных 0,1% — правдоподобно; если руб., порог 15 млрд недостижим | Организаторы/BA | Порог FM-01/F-01 в `config`, меняется одной строкой |
| OQ-03 | NULL продуктовых флагов у `PROSPECT` = «неизвестно», а не «нет продукта»? | Организаторы | Влияет на E-01..E-03: для потенциальных клиентов own-компоненты пустые |
| OQ-04 | Полный справочник страна ФТС → валюта и риск-тир страны | BA | E-03/E-12 используют словарь; отсутствующие страны → prior отрасли |
| OQ-05 | Семантика `NEGATIVEMARK` не совпадает с описанием поля | Организаторы | F-12 считается «как есть», в формулы не входит (P2) |
| OQ-06 | GR-01: компонента из 750 юрлиц через общий `GROUP_ID`/физлицо — реальный кластер или артефакт? | Организаторы | Влияет на FM-23 (распространение по группе) и F-11 |
| OQ-07 | Период агрегации платежей (`PAY_AMT`, `PAY_CNT` по паре) не указан в кейсе | Организаторы | G-10 (частота) интерпретируется как «платежей за период»; обороты сравниваются относительными величинами |

## 4. Паспорта метрик — P0

Формат — по разделу 4.1 ТЗ. Распределения приводятся в Приложении A (перегенерируется на каждом прогоне); здесь — только устойчивые к данным свойства.

### F-01. Крупный бизнес и масштаб

| Поле | Содержание |
|---|---|
| ID, группа | F-01, профиль клиента (F) |
| Определение и формула | `is_large = 1[REVENUE_COMPANY >= 15 млрд]`; `rev_log10 = log10(REVENUE_COMPANY)`. Функции: `metrics_f.f01_scale`, `formulas.fm01_is_large` |
| Входные поля | `REVENUE_COMPANY` |
| Единицы и диапазон | `is_large` ∈ {0,1}; `rev_log10` ∈ [0, 13] при разумных выручках |
| Обработка пропусков | Пустая выручка → оба поля NULL (компонент не учитывается) |
| Граничные случаи | Выручка ≤ 0 → `rev_log10` = NULL; единицы измерения не подтверждены (OQ-02) — порог вынесен в параметр |
| Наблюдаемое распределение | Приложение A; доля `is_large=1` = 0,1% на реальном прогоне |
| Проверки | (1) `is_large` ∈ {0,1} для 100% строк; (2) монотонность: `is_large=1` ⇒ выручка ≥ порога |
| Использование | FM-21 (индекс уязвимости к ставке), FM-24 (ScaleFactor), фильтры ленты |
| Как объяснять пользователю | «Крупный бизнес — выручка от 15 млрд рублей в год» |
| Чего нельзя утверждать | Порог 15 млрд не подтверждён единицами данных; до OQ-02 не утверждать долю крупных как факт |
| Владелец, частота | DA, при каждой загрузке данных |

| Как объяснять пользователю | «Сколько денег входит и выходит по расчётам компании» |
| Чего нельзя утверждать | Абсолютные обороты не сравнивать с внешними объёмами: период агрегации неизвестен (OQ-07) |

| Определение и формула | `HHI_in = SUM(s_i²)`, `s_i = PAY_AMT_i / in`; `HHI_out` аналогично. Функции: `metrics_g.g03_hhi`, `formulas.fm05_hhi` |
| Входные поля | `PAYER`, `BENEFICIARY`, `PAY_AMT` |
| Единицы и диапазон | [1/n, 1]; ближе к 1 — выше зависимость от одного контрагента |

| Владелец, частота | DA, при каждой загрузке |
