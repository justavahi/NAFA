# Одноэкранный интерфейс NAFA

Дата: 26.10.2026. Визуальный ориентир — [раздел для бизнеса Альфа-Банка](https://alfabank.ru/sme/).
Реализация самостоятельная: красный акцент, светлая рабочая область, компактная
навигация, округлённые панели. Внешние шрифты, библиотеки компонентов и изображения
для работы страницы не нужны.

## Рабочая логика

На desktop лента и выбранное событие находятся в одном экране. Прокручивается
содержимое панелей, общий документ не растёт. Контекст компании и роль занимают
верхнюю строку. На телефоне лента и разбор переключаются кнопкой «К ленте».
Карточка сохраняет вкладки и закреплённый ввод вопроса.

Выбор новости показывает её исходный текст. Кнопка «Разобрать влияние» явно
запускает AI. Простое чтение и переключение ленты не вызывают модели.
Карточки кэшируются в памяти для текущего контекста; обновление ленты сбрасывает
этот кэш. Загрузка, недостаток данных, отклонённый ответ и demo обозначены явно.

## Сверка интерфейса с требованиями

Основание: `case.pdf`, страницы 9–10; спецификация UI-01…UI-13 в разделе 5.7
`docs/business/05_reference_metrics_sources_formulas.md`.

| Требование | Где реализовано / граница проверки |
| --- | --- |
| UI-01 / C09: заметная точка входа | Постоянный пункт «Аналитика» в оболочке прототипа. Встраивание в настоящий Альфа-Бизнес не выполнялось |
| UI-02 / C01, C06: компания и роль | Компактная верхняя строка; шесть ролей. Клиент видит только свою компанию |
| UI-03: топ-5 и релевантность | Левая панель, фактор события и баллы соответствия. До извлечения сортировка предварительная; знаки рисков не выдумываются для ещё не разобранного события |
| UI-04 / C02: шесть смысловых блоков | Обзор: событие, компания, последствия, действия, позиция банка; основания доступны во вкладках |
| UI-05 / C03: происхождение | Раздельные подписи «Факт из источника», «Позиция Альфа-Банка», «Вывод AI». У банковских цитат дата и пометка устаревания; у AI внутренняя оценка обоснованности |
| UI-06 / C12: признаки и самопроверка | «Как получен вывод»: признаки из сохранённого реестра, этапы и журнал. Новый read-only `/cards/{id}/basis` закрыт той же проверкой владельца, что trace |
| UI-07 / C10: уточнение | Закреплённый ввод, история диалога сворачивается и не требует перехода на страницу |
| UI-08: первоисточник | «Источники»: ссылка, точная цитата, дата; для аналитики банка — оригинальная страница PDF |
| UI-09 / C05: своя новость | Диалог с текстом или URL и необязательной датой |
| UI-10, P1: предложение банка | Отображается отдельным подписанным блоком, только если карточка содержит разрешённое предложение |
| UI-11, P1: сценарии | «Расчёты»: ставка, валютный курс, инфляция; вводные пользователя, деньги считает код |
| UI-12, P1: мониторинг качества | Существующие admin API качества/бюджета сохранены. Отдельная визуальная панель Q-04/Q-09/Q-13 и независимые оценки не реализованы этим редизайном |
| UI-13, P1: обратная связь | «Полезно», «Не помогло» и необязательная причина |

## Проверка

`scripts/check_browser.py` запускает настоящий HTTP-сервер и браузер с
контролируемыми ответами моделей. Проверены все шесть переключений роли,
просмотр без LLM-вызовов, отклонённый разбор, новая новость, карточка, вопрос,
три калькулятора, источники, признаки компании, trace, обратная связь с причиной
и выход. Геометрия проверена на 1440×1000, 1280×800 и 390×844: документ помещается
в viewport без горизонтального скролла. Проверены ошибки JavaScript.

Отчёт: `browser_check.json`. Скриншоты создаются в `.local/audit/browser_*.png`.
Это подтверждение технического сценария и геометрии, а не независимая оценка
качества LLM, банковская интеграция или полная приёмка C01–C12.
