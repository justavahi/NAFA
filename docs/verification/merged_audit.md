# Проверка объединённого NAFA по ТЗ

Дата: 26.10.2026. База — main `b0d3c40`; исправления и проверки находятся локально
в `roreternity/merged-acceptance-audit`. Точные хэши проверенного кода —
в `test_results.json`. **Полное соответствие кейсу пока не подтверждено.**

Источники требований: `case.pdf` (формат сдачи на стр. 8, C01–C12 на стр. 9–10,
ограничения на стр. 11–12, модели в Приложении 3) и декомпозиция команды
`docs/business/02_TZ_backend_parsing.md`, `03_TZ_data_analyst.md`, `04_TZ_prompt_engineer.md`.
Численные цели PD@5 ≥ 0,40 и Q-08 ≥ 4,0 взяты из внутреннего ТЗ команды;
цель 4,5 — дополнительная, не отдельное требование организаторов.

Дополнительно реализованы автоматический CaseInput из новости и DA, защищённый
вход, клиентская изоляция, frontend и единый контейнерный entrypoint. Браузерный
тест проходит на настоящем HTTP API: новая новость → извлечение → DA → карточка →
критик → вопрос → расчёт → feedback → trace → выход, desktop и mobile.
Ответы моделей в нём контролируемые. Подробности — browser_check.json.
Исходный baseline сохраняет provisional-статус; его тесты проверяют именно это,
а новые PE/UI-тесты проверяют основной entrypoint. Старые xfail сняты с таким разделением.

В этой итерации **нет удалённых LLM-вызовов**, обучения или автоматически
придуманных человеческих оценок. Сетевой API моделей в интеграционных тестах
заменён контролируемыми ответами; TCP-проверка блокирует mock до вызова модели.
Внешние новостные источники вживую и 7-дневное окно их надёжности не проверялись.

## Реальные данные пересчитаны текущим кодом

Подробности и хэши входов — `da_participant.json`, без сырых идентификаторов:

- 85 525 строк компаний, 1 380 585 платежей, 12 514 связей;
- 85 514 уникальных компаний в согласованных таблицах признаков/экспозиций;
- экспозиции в [0,1], чистая процентная позиция в [-1,1], ключи уникальны и совпадают;
- после исправления F10: existing 41 968, potential 36 688, неизвестно 6 858;
- один конфликтующий ID дедуплицирован по первой строке; для приёмки реальных
  карточек его надо исключить либо согласовать правило с владельцем данных;
- дата агрегатов, единицы выручки и семантика части полей остаются неподтверждёнными.

Расчёты выполнены с pandas 3.0.2 из окружения объединённого backend.
Сырьё не копировалось в Git. Реальные клиенты через LLM в этой проверке не прогонялись.
Синтетический DA smoke отдельно: 60 компаний, 400 платежей, 80 связей.
Демонстрационные метки качества и графики не использовались как результат модели.

## Найденные и исправленные дефекты

1. **Параллельные HTTP 500.** SQLite-соединение создавалось и использовалось
   разными потоками FastAPI. Воспроизведено 40 параллельными `/health`;
   исправлена настройка соединений при сохранении одного соединения на запрос.
2. **Калькуляторы.** `{}` ошибочно переключался в обычный диалог; NaN/Infinity
   и переполнение приводили к HTTP 500 и могли сохранять некорректный ответ.
   Теперь входы и результаты конечны, ошибка — 422, ответ не записывается.
3. **Исторический контекст.** Прямая генерация могла открыть будущую новость,
   а позиция банка выбиралась без `as_of`. Исправлены отсечения, передача даты
   и отклонение некорректных дат вместо молчаливой подстановки текущей даты.
4. **F10.** Реальное значение CLIENT не распознавалось как existing.
   Исправлено точным сопоставлением; CLOSE_CLIENT и NULL не угадываются.
5. **Holdout.** Экспорт сохранял отложенные события и в файле для калибровки.
   Теперь development/holdout раздельны, полный архив имеет отдельное имя;
   калибровка отбрасывает компоненты без development-меток.
6. **Сырые ID в журнале DA.** Дедупликация печатала исходные идентификаторы.
   Теперь только количество; заодно устранён риск сортировки смеси NULL и строк.
7. **Ложная ручная проверка PDF.** Автосравнение чисел помечало chunk как manual,
   даже если другая строка для него не совпала. Теперь по умолчанию сравнение
   не повышает доверие; явное подтверждение после проверки оригинала требует
   совпадения всех строк. Неподписанные chart_estimate не подтверждаются как факт.
8. **Разрыв PE ↔ Backend.** Добавлен мост за существующими API-адресами,
   общий шлюз/SQLite, независимый диалог, атомарное сохранение контекста и карточки,
   блокировка результатов replay/evaluation и непринятых ответов.
9. **Совместимость шлюза.** Добавлены разрешённые request_options с учётом в ключе
   кэша, обработка пустого content и запрет кэшировать пустой/обрезанный ответ.
   API ID моделей приведены к сохранённой инструкции организаторов.
10. **Сборка окружения.** Убрана неиспользуемая httpx2, не входившая в requirements;
    lock обновлён. Экспорт тестового gateway в merged layout берёт текущий store,
    а не исторический snapshot из другой структуры. Зафиксирован Python 3.12.

Уточнение к старому отчёту PE: `file_hash` кэша PDF — это
`SHA256(имя файла + байты)`, а не SHA256 одних байтов. Для DOC-07 это проверено;
различие двух хэшей само по себе не означает другой источник или повреждение.

## Блокеры сдачи

1. Живая оценка нового connected_v1 на независимых событиях. Инфраструктурные
   проверки не доказывают Q-08 ≥ 4,0/4,5 или достижение PD@5 ≥ 0,40.
2. Производственное встраивание в банковский контур и управление доступом через
   реальную систему банка. Локальный прототип использует коды и серверные сессии.
3. Человеческая разметка 40–60 пар двумя аналитиками, согласие κ ≥ 0,6,
   замороженный holdout, независимые Q-08 ≥ 4,0 и факт-аудит по внутреннему ТЗ.
4. Ручная проверка исходных PDF, исправление смысловых ошибок кэша,
   отсутствующий DOC-10 и подтверждённый прогон разрешённой VLM.
5. RUB-тарифы, cost_card/суточная ёмкость в 400 ₽, замеры p50/p95 на настоящих
   моделях. Нулевые тарифы в конфиге не доказывают бесплатность.
6. Docker clean-host build и единый запуск всего приложения. Здесь Docker CLI
   установлен, но daemon недоступен; сборка/контейнерный запуск не подтверждены.
   Корневой Dockerfile/Compose теперь включает PE/DA/UI; compose config проверен.
   Исторический compose в store сохранён для baseline.
7. Корневой комплект сдачи: итоговый commit/tag и проверка лицензий зависимостей при
   внешней упаковке. Инструкции полного пользовательского демо добавлены в README.

## Повторить проверки

```bash
uv run --project src/store python scripts/verify_merged.py
```

Результаты — `test_results.json`, `server_startup.json`, `profile_scenarios.json`,
`corpus_check.json`, `da_synthetic.json`, `browser_check.json`. Логи, временные БД и персональные данные
остаются в игнорируемом `.local/`. Схема PE-подключения — `backend_handoff.md`.

Реальные CSV отдельно, без публикации содержимого:

```bash
uv run --project src/store --with matplotlib==3.11.2 --with tabulate==0.10.0 \
  python scripts/check_da_pipeline.py --data-dir /absolute/path/to/participant-data
```

Все автоматические проверки могут быть зелёными при `full_case_acceptance=false`:
это честный результат для текущей реализации, а не подтверждение полной готовности.
