## Что подготовлено

- `pe/schemas.py`: строгие контракты пяти выходных объектов из §3.3.
- `pe/cli.py`: экспорт JSON Schema и локальная валидация ответа модели.
- `prompts/token_budget.csv`: таблица замеров, без вымышленных цен.
- `tests/test_schemas.py`: проверки формы и происхождения утверждений.
- `pe/evidence.py`: реестр доказательств и проверка ссылок карточки.
- `04_ml_architecture.md`: адаптация предложенного ML-пайплайна к формулам NAFA,
  варианты архитектуры, протокол оценки и оговорки к BIQ.
- `prompts/manifest.json` и PRM-01..17: версионированные промпты и исполняемые входные/выходные контракты.
- `pe/pipeline.py`, `pe/run.py`: сквозная сборка, проверка карточки и адаптер общего шлюза.
- `05_first_run.md`: команды локального реплея и реального запуска.
- `pe/benchmark.py`, `pe/audit_cases.py`, `pe/metrics.py`: 1000 синтетических
  случаев аудита, реальный вызов GLM через шлюз, отдельный отчёт и loss.
- `06_evaluation.md`: протокол теста, ограничения метрики и подготовка данных SFT.

Внутренняя карточка преобразуется в формат backend через `pe.integration`;
разрешённые агрегаты DA загружаются через allowlist. Структурную проверку
дополняют проверки доказательств, чисел и знаков, затем независимый PRM-07.
Сквозное подключение к актуальному сервису и реальным выгрузкам проверяется
на стороне общего приложения.

## Интеграционные решения

1. Числа F/G/E/FM и `effect_sign` приходят из кода DA. Модель получает готовые
   значения и формулирует текст, не пересчитывая их.
2. Новости и документы считаются недоверенным вводом; в промптах они
   обрамляются блоком `untrusted_source` с ID источника.
3. Каждое утверждение карточки имеет слой (`fact`, `bank_view`, `ai_inference`)
   и ID источника. Позиция банка включает дату, документ и страницу.
4. Генерация PRM-05/06 и критика PRM-07 идут через разные семейства моделей.
5. `cost_card` и дневной расход рассчитываются после получения тарифов и
   измерений. Лимит кейса 500 ₽/сутки, рабочая цель 400 ₽/сутки.

## Нерешённые зависимости

- В `data-analysis` золотой набор ещё размечается; CH-08 ждёт ряды M от backend.
- Цены моделей в `backend-parsing:store/config/models.yaml` равны 0 как
  заглушки; их нельзя принимать за бесплатные вызовы.
- API ID и общий доступ подтверждены инструкцией организаторов; ключ хранится локально.
- Экспертный аудит реальных карточек и подтверждение тарифов остаются внешними условиями приёмки.

## Локальный запуск

```bash
uv sync --dev
uv run pytest
uv run python -m pe.cli EventExtraction > /tmp/event_extraction.schema.json
uv run python -m pe.cli EventExtraction path/to/response.json
uv run python -m pe.cli InsightCard card.json --ledger ledger.json
```

Реальные файлы Приложения 1 теперь получены и обработаны закреплённым DA; исправление категорий клиента и сквозной A/B описаны в [08_real_participant_data.md](08_real_participant_data.md). Полная экспертная приёмка и рабочий API backend остаются отдельной проверкой.
