## 0. Цель роли и критерии успеха

**Цель:** превратить данные о клиентах и платежах в профиль и вектор экспозиций, реализовать и откалибровать формулы ранжирования, построить золотой набор и метрики качества, подготовить графики. Всё, что считается числом, считает Data Analyst кодом, а не LLM.

| Критерий кейса | Что должен обеспечить DA |
|---|---|
| C01 | Метрики F, G, E; графы GR-01..GR-03; ранжирование FM-06..FM-13; точность персонализации Q-05; доказательство, что лента меняется (Q-07) |
| C02 | Правило знака FM-14 и сценарные калькуляторы FM-15 |
| C03, C04 | Верификация записей bank_view и чисел из корпуса; метрики Q-01..Q-03, Q-09, Q-11, показатель трассируемости Q-28, индекс галлюцинаций Q-29 |
| C05 | Hold-out набор и Q-10 |
| C08 | Метрики Q (включая Engagement Rate Q-30 и воронку Q-31), золотой набор, панель, регламент раздела 10 справочника |
| C12 | Разложение скора на компоненты (CH-14) |
| R05 | Профилирование, правила пропусков, F-13, Q-17 |

### 3.1 Проверки при профилировании (WP-D1)

| Блок | Что проверить | Критерий / действие |
|---|---|---|
| Размер | Строки и уникальные ключи в каждом файле | Нет дублей `SYNTHETIC_U`; различия с кейсом фиксировать |
| Масштаб | Единицы REVENUE_COMPANY; доля клиентов с выручкой ≥ 15 млрд ₽ | Подтвердить определение крупного бизнеса (FM-01); если доля мала, сообщить BA |
| Пропуски | Доля `NULL` по каждому полю | Решения по обработке в паспортах метрик |
| Словари | Значения ECO_MARK_LABEL, OKFS_NAME, ORG_TYPE, градаций возраста и численности | Выписать полный словарь; определить `growth_flag` и `is_state_related` |
| Продукты | Значения флагов (0/1, Y/N, NULL) и их соотношение для действующих и потенциальных клиентов | Для потенциальных клиентов NULL не равно «нет продукта» |
| ФНС и СПАРК | Совпадение градаций численности | Доля конфликтов, пример (CH-03) |
| ВЭД | FTS_FLAG и FTS_COUNTRY_NAME: непротиворечивость, список стран | Справочник страна → валюта |
| NEGATIVEMARK | Распределение значений и связь с другими полями | Сообщить BA (OQ-03) |
| Группы | GROUP_ID: размеры групп, одна ли отрасль в группе | F-11 |
| Графы | Размеры связных компонент GR-01 (через физлиц и GROUP_ID); число рёбер и плотность GR-02; доля контрагентов, найденных среди клиентов (известен профиль SP) | Решение о глубине FM-22 (k ≤ 2) и о покрытии контрагентов |
| География | Доля CITY/REGION пустых; согласованность с RC_NAME | F-07 |
| Платежи | Платёжные идентификаторы, отсутствующие среди клиентов; нулевые и отрицательные суммы; самоплатежи; PAY_CNT = 0 | Правила очистки |
| Покрытие | Распределение клиентов по SP; сколько клиентов в каждом профиле | Профили без данных помечаются |
| Выбросы | Экстремальные значения выручки и платежей | Winsorization для графиков, не для расчётов |

- RSK-04: сначала профилирование, потом всё остальное: единицы выручки и словари меняют пороги.
- RSK-07: размер долга и направление ВЭД неизвестны; не пытайтесь их «оценить» в метриках, это превращается в выдумку. Используйте двухветвевую логику FM-14 и калькулятор FM-15 по вводным пользователя.
- RSK-13: делайте P0, не расширяйте объём до всех метрик каталога, пока не пройдены тестовые векторы.
- Матрица SP × фактор является гипотезой; если данные её опровергают, предлагайте правку с доказательством, а не подгоняйте метрики.
